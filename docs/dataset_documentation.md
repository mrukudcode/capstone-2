# Dataset Documentation

All numbers below were calculated directly from the actual files in this
repository at the time of writing (via `scripts/validate_dataset.py` and
direct CSV/JSON inspection) — none are approximated.

## 1. What datasets exist
- **Source documents** (`data/structured/source_documents.csv`): 5 rows,
  each a real insurer or regulatory document, extracted to text.
- **Policy inventory** (`data/structured/policy_inventory.csv`): 4 rows,
  each a distinct policy version.
- **Rule candidates** (`data/structured/policy_rule_candidates.csv`): 59
  rows, each an individual extracted rule with a page citation.
- **Synthetic claims** (`data/synthetic/claims.json`): 28 rows, each a
  fabricated test claim exercising one real rule.
- **Dataset validation report** (`data/structured/dataset_validation_report.json`):
  machine-generated counts/errors/warnings, regenerated by
  `scripts/validate_dataset.py` on every run (not hand-edited).

## 2. Where every dataset file is located
See `data/README.md` for the directory-by-directory breakdown.

## 3. Which documents are real
All 5 documents in `source_documents.csv` are extracted text of real,
publicly published documents (see column `source_url` in that file for
each one's exact origin). None are fabricated or synthesized.

## 4. Insurer policy documents (4 of the 5)
1. `STAR_ASSURE_2026_CIS` — Star Health Assure Insurance Policy, Customer
   Information Sheet, 20 pages.
2. `HDFC_OPTIMA_SECURE_2026_POLICY_WORDING` — HDFC ERGO my:Optima Secure,
   full Policy Wording, 60 pages (per its own Table of Contents; ~42

3. `HDFC_OPTIMA_SECURE_2026_CIS` — HDFC ERGO my:Optima Secure, Customer

4. `HDFC_OPTIMA_SECURE_2021_HISTORICAL` — HDFC ERGO my:Optima Secure,
   combined CIS+Policy Wording, 24 pages, the historical 2021 version.

## 5. Regulatory documents (1 of the 5)
`IRDAI_MASTER_CIRCULAR_2024` — Master Circular on Health Insurance

## 6. Records extracted from real documents
All 59 rows of `policy_rule_candidates.csv` are extraction attempts from
the 5 real documents above. Each row's `source_document`, `source_page`,
and `source_text` columns point back to the specific document and page.
- Insurer-sourced rules: 49
- Regulatory (IRDAI) rules: 10

## 7. Which records are synthetic
All 28 rows of `data/synthetic/claims.json`, and only those. Every row
carries `"claim_provenance": "SYNTHETIC"` and
`"expected_result_provenance": "DERIVED_FROM_REAL_RULE"` explicitly.
**No row in `policy_rule_candidates.csv`, `source_documents.csv`, or
`policy_inventory.csv` is synthetic.**

## 8. How policy rules were extracted
Documents were fetched via a web-fetch tool that performs text extraction
(this session's environment could not retrieve raw PDF bytes — see §17
below). The extracted text was then read directly and specific clauses
(waiting periods, sub-limits, exclusions, deadlines, etc.) were
transcribed into `policy_rule_candidates.csv` rows with the exact source
text quoted in the `source_text` column and the printed page number in
`source_page`. No rule value was filled in from general insurance-domain
knowledge — categories not found in the source are marked
`NOT_FOUND_IN_SOURCE` or `NOT_SPECIFIED_IN_SOURCE` rather than guessed
(this rule is honored: neither placeholder string appears misused as a
numeric value anywhere in the current 59 rows).

## 9. How page citations are preserved
Each `data/raw/**/*.txt` file uses `[PAGE N]` markers reflecting the
source PDF's own printed page numbers (not an arbitrary renumbering).
Each rule candidate's `source_page` column cites that same page number.

## 10. What "provenance" means in this dataset
Three provenance tiers are used consistently:
- **INSURER_DOCUMENT** / **REGULATORY_DOCUMENT** — a rule extracted
  directly from a real source document (columns: `provenance` in
  `policy_rule_candidates.csv`).
- **SYNTHETIC** — a fabricated test claim (`claim_provenance` field in
  `claims.json`).
- **DERIVED_FROM_REAL_RULE** — an expected test result computed from a
  real rule's actual threshold, not invented
  (`expected_result_provenance` field in `claims.json`).
- **DERIVED_LOGIC_NOT_FROM_SOURCE_RULE** — used internally by
  `backend/app/rules/policy_status.py` for two checks (policy-cancelled,
  policy-expired) that are reasonable business logic but are NOT backed
  by a specific extracted clause — documented explicitly in that module
  rather than misattributed to a source page.

## 14. Known missing/uncertain documents
- Star Health Assure's full **Policy Wording** PDF (as opposed to the CIS)
  was located during search but never ingested — only the CIS is in the
  dataset for Star. This is an honest gap, not a silent omission.
- ICICI Lombard, Care Health, and any third/fourth insurer were never
  attempted (time-boxed out in the original session).
- HDFC 2026 Policy Wording: only ~pages 1-42 of its own stated 60 were
  extracted; Sections E and Annexures A-C are missing.

## 15. HDFC UIN conflict
Two official `hdfcergo.com`-hosted documents for the same current product
cycle print two different UINs (`HDFHLIP26058V082526` on the Policy
Wording vs `HDFHLIP25041V062425` on the CIS). Full detail, evidence
table, and recommended next step: `docs/HDFC_ERGO_UIN_REVIEW.md`. All 17
affected rule rows are marked `review_status=NEEDS_REVIEW` and are
excluded from automatic rule-engine evaluation (verified: a claim against
`hdfc_optima_secure_2026_v1` evaluates zero automatic rules and returns
`HUMAN_REVIEW_NEEDED`).

## 16. IRDAI source verification limitation
`irdai.gov.in` blocks automated fetch in this environment
(`ROBOTS_DISALLOWED`). The Master Circular text in this dataset comes from
a full-text, verbatim third-party republication (taxguru.in) that matches
the official reference number, date, and CGM signatory exactly, but was
never fetched directly from irdai.gov.in itself. Recorded as
`official_source=false` in `source_documents.csv` for this reason, and
flagged for re-verification with browser-based access in a future
session.

## 17. Hash limitations
Every one of the 5 source documents has `hash_type=EXTRACTED_TEXT` and
`original_file_available=false` in `source_documents.csv` — none is
`ORIGINAL_FILE`. This is because this session's tools (`web_fetch`,
`bash_tool`) could not retrieve raw PDF bytes: `web_fetch` returns
extracted text regardless of its `web_fetch_pdf_extract_text` parameter in
this environment, and `bash_tool`'s network egress is restricted to
package-registry domains, excluding every insurer/regulator domain used
here. This is disclosed per-document, not hidden.
